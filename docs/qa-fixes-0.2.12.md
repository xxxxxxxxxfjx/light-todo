# 0.2.12 · 桌宠与应用退出生命周期

问题：主窗口关闭后原本只是驻留托盘；便携启动器被单独结束时没有约束 Electron 子进程树，而且保留了短时间异常退出后的兼容重试。

修复：

- 关闭主窗口会退出应用，最小化仍可继续使用桌宠。
- 主窗口直接销毁、页面关闭或主渲染进程被结束时，同样整体退出，不留下托盘和桌宠。
- 退出时同步保存桌宠位置、停止刷新和位置保存定时器、销毁窗口；拒绝退出过程中的重新创建和延迟 ready-to-show。
- 忽略已退出桌宠窗口发出的迟到事件，避免关窗过程触发异常。
- 启动器以挂起状态创建子进程，先加入 Windows kill-on-close Job Object，再恢复执行，避免子进程在被纳管前创建后代。
- 启动器被 kill 时系统回收完整子进程树；运行时被 kill 时启动器直接结束，不重试，也不弹出会继续留在后台的退出错误对话框。

验证：`node scripts/test-launcher.cjs` 编译隔离测试程序并实际验证默认目录、日志不可写、参数传递、异常只启动一次、kill 启动器后子孙进程消失、kill 运行时后孙进程消失且无重启。

成品强杀测试：只对最外层 EXE 执行 Stop-Process（不使用进程树结束参数），随后查询确认本次运行时、内层启动器及渲染进程全部退出。

最终验证通过：强杀后观察超过 115 秒，进程未重现。官方 Playwright MCP 关闭重建后的主页面，随后查询进程为空，内外启动器日志均为 `exit=0`；SQLite 中原有任务仍存在。页面关闭时 MCP 的 Target closed 是整个应用退出的预期结果。包内全部 10 个构建文件与最终构建一致；SHA-256 在交付目录 `checksums.json`。

构建版本：0.2.12；交付到 `release/0.2.12/`。
