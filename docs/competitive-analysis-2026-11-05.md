# 轻单 LightTodo 竞争力评估与功能路线建议

> 输入：`docs/feature-survey.md`（2026-11-02，19 款竞品）、`docs/prd-v1.md`、当前 0.2.12 代码与实测
> 日期：2026-11-05 ｜ 结论口径：产品/市场判断，不是精确市场份额预测

---

## 0. 一句话结论

**有竞争力，但赢面不在“做一个功能更全的 Todoist/TickTick”，而在“Windows 上最快、最可信、最顺手的中文本地待办”。**

- 作为 **Windows 版 Things 3 / 隐私优先个人待办**：当前约 **7.5/10**，方向正确，补 5～6 个日常闭环就能打。
- 作为 **TickTick / Todoist 全能替代品**：当前约 **4.5/10**，功能面差距太大，不建议现在追。
- 作为 **AI 日程管家（Motion/Akiflow）**：当前约 **2/10**，不是这一代产品该做的事。

关键战略选择：**调研推荐的是“方案 B 全能工作台”，但当前产品实际走的是“方案 A 极简高效 + 日历 + 桌宠”。这不是错，反而更容易建立差异；但必须二选一，不能既想要 B 的功能密度，又想要 A 的速度和简洁。**

## 1. 市场空位还在不在？

### 1.1 调研里的空位仍然成立

调研的五条判断，今天看仍然成立：

1. 纯清单已是及格线，任务/子任务/标签/重复/提醒/日历大家都有。
2. Todoist 强在捕获与生态，但 Windows 端性能口碑差；TickTick 功能最全，但 Windows 端卡顿/耗电、AI 不支持 Windows；Things 3 手感和键盘流最好，但没有 Windows 版。
3. AI 正从助手走向 Agent/MCP，但大多云端、付费墙后。
4. 国内用户的农历/调休、四象限、习惯、倒数日、多通道催办是真实需求，但小黄条/时光序/敬业签的 Windows 稳定性都不算好。
5. “Windows 上最快、最像原生、最省电的 Todo” 仍是空位。

### 1.2 但这个空位比想象中窄

空位的准确描述不是“Windows 没有好 Todo”，而是：

> **“不想登录云账号、每天 10–50 条任务、键盘操作、在意启动速度和数据归属的 Windows 个人用户。”**

这群人愿意为“快 + 干净 + 数据是我的”买单，但人数有限，且很容易被 Microsoft To Do 的“免费 + Outlook”吸走。所以：

- **不要用功能数量去打 Todoist/TickTick**，会输。
- **要用“启动快、输入快、离线可用、数据可带走、Windows 原生细节”去打**。
- **不要先做协作/团队/企业**，那会同时丢掉“轻”和“本地”的品牌。

### 1.3 2026 年的新变量：AI/MCP 不是刚需，但会成为高端标配

调研已经指出 Todoist/TickTick/Superlist/Akiflow/Sunsama/Reclaim 都在做 MCP/Agent。对轻单来说：

- **短期不要做“AI 排程/自动重排”**：依赖日历、时长、模型，工程风险高，且会破坏“快”的定位。
- **优先做 MCP Server**：让 Claude/ChatGPT 通过本地 MCP 读写轻单任务，成本远低于做一套 AI UI，也符合“本地优先 + 可选 AI”。
- **AI 能力必须可关闭、可换 Key、失败可降级**，不能成为核心路径的单点依赖。

## 3. 相对竞品的竞争力

### 3.1 分维度判断

| 维度 | 轻单 | 对比结论 |
|---|---|---|
| 捕获速度 | 强：全局快捷键 + 中文 NLP + 托盘 + URL | 不输 Todoist/TickTick；比 Things 更适合中文 |
| 任务模型 | 中上：清单/文件夹/标签/子任务/优先级/两种日期/重复 | 缺 checklist/模板/附件，但核心够用 |
| 规划视图 | 中：今天/7 天/全部/日历/月周日 | 缺收件箱、看板、四象限、拖拽排序 |
| 提醒闭环 | 中：Toast + 多档提前量 | 缺通知按钮、稍后、持续提醒；TickTick/敬业签更强 |
| 数据信任 | 强：SQLite + 备份 + 导出 + 便携 | 明显优于云优先产品，是核心卖点 |
| Windows 集成 | 强：托盘/全局快捷键/Jump List/URL/便携/桌宠 | 比 Todoist 更“Windows 工具”，但缺任务栏角标/Mica |
| 键盘体验 | 中上：主要操作有快捷键 | 缺命令面板、自定义、撤销；Things 仍是天花板 |
| 性能 | 未知：本机开发环境启动约 4s，打包测试也受环境影响 | **最大风险；没有可复现的对外数据前，不能把“最快”当既成事实** |
| AI/MCP | 无 | 高端市场会掉队，但对当前目标用户不是第一优先 |
| 同步/移动/协作 | 无（有意不做） | 会限制用户规模；短期用导入导出/ICS 解决 |

### 3.2 目标人群匹配度

| 人群 | 匹配度 | 判断 |
|---|---|---|
| 从 Things 3 转到 Windows 的用户 | 8/10 | 最匹配；补 undo/拖拽/markdown/quick entry 即可 |
| 隐私/本地优先用户 | 8.5/10 | 最强卖点；可加可选加密/自建同步 |
| 中文知识工作者 | 7/10 | NLP 很好；缺农历/调休/中文搜索 |
| 想从 TickTick 迁移的用户 | 5/10 | 缺少看板/习惯/番茄/日历同步/统计，短期接不住 |
| 团队/项目管理 | 2/10 | 明确不做 |
| AI 日程管家用户 | 2/10 | 不做 Motion 路线 |

### 3.3 竞争位置图（文字版）

```
功能密度 / 全能
        ↑
        │   TickTick / Todoist / Motion / Akiflow
        │        （云、重、功能全）
        │
        │        时光序 / 敬业签
        │        （国内多通道/大杂烩）
        │
        │              ★ 轻单（目标：快、轻、本地、中文）
        │
        │   Things 3（无 Windows）      小黄条（桌面挂件）
        └────────────────────────────────────────→
          本地 / 快 / 轻                     云 / 协作 / 重
```

轻单不应该往右上角挤；应该把左下角的“快、轻、本地、中文”做到极致，再向右上角伸出一两个触角（ICS/可选同步/MCP）。

## 4. 建议新增 / 改进的功能

### P0：不补会直接伤害“最快/最好用”的定位（建议 4–6 周）

| 优先级 | 功能 | 为什么现在做 | 工作量 |
|---|---|---|---|
| P0-1 | **性能基准与优化**：打包版冷启动/内存/1 万条滚动基准；TaskList 虚拟滚动；桌宠延迟加载/可关闭 | “快”是唯一不能输的卖点；目前 TaskList 仍全量渲染，没有干净机器数据 | 1–2 周 |
| P0-2 | **收件箱 / 未分类**：全局捕获默认进收件箱，不污染今天；提供键盘 triage | 调研 D1 是 P0；现在无日期任务默认进今天，长期会变成垃圾场 | 3–5 天 |
| P0-3 | **通知闭环**：Toast 上“完成/稍后 10 分钟”；错过提醒合并摘要；持续提醒；任务栏角标 | TickTick/敬业签的强项；当前只有“点开任务”，日常提醒不可闭环 | 1 周 |
| P0-4 | **列表手感**：拖拽排序、行内改标题、Ctrl+Z 撤销（完成/删除/移动） | Things 的核心手感；PRD D7/§6.4 已承诺但未实现 | 1 周 |
| P0-5 | **Markdown 预览 + checklist**：备注编辑/预览；任务内勾选步骤 | 知识工作者刚需；当前只提示支持 Markdown，实际纯文本 | 1 周 |
| P0-6 | **FTS5 搜索 + 分页**：中文分词/前缀匹配，10k 任务毫秒级；去掉 60 条硬上限 | 目前 LIKE + LIMIT 60，和“万级任务”定位不匹配 | 3–5 天 |
| P0-7 | **数据出口补齐**：CSV 导出、MS To Do 导入、ICS 导出 | “数据可带走”是信任卖点；目前导出/导入不完整 | 3–5 天 |

### P1：形成差异化（6–10 周）

| 功能 | 价值 | 备注 |
|---|---|---|
| **命令面板 Ctrl+K + 自定义快捷键** | 键盘流的入口；Things/Akiflow 的强项 | 比再加一个视图更符合定位 |
| **任务栏进度/角标** | Windows 原生差异点，成本低 | 今日完成度/剩余数 |
| **ICS 导入导出 + 只读系统日历** | 让日历真正可用，不依赖云 | 先 ICS，再做 Google/Outlook OAuth |
| **农历/节气/法定调休** | 中文刚需；海外产品普遍缺失 | 影响重复/提醒/日历 |
| **周复盘/完成热力图** | 留存与自我反馈 | 不要做重型 BI |
| **模板/检查清单** | 重复性工作流 | 比附件更轻，优先于附件 |
| **桌宠迷你清单增强** | 已有差异点；做成 always-on-top 今日清单 | 默认可关，避免“卖萌”影响专业感 |

### P2：等留存验证后再做（3–6 个月）

| 功能 | 判断 |
|---|---|
| **可选同步（WebDAV/S3/自建）** | 最大用户缺口，但工程/冲突合并成本高；先做导出/ICS，验证有人愿意为同步付费 |
| **MCP Server + 可选 AI（自带 Key）** | 比做 AI 聊天 UI 更符合本地优先；先 MCP，再做任务拆解/今日排程 |
| **浏览器扩展/邮件转任务** | 获客入口；需要商店审核与后端 |
| **附件/图片** | 会复杂化备份/同步；非当前核心 |
| **任务依赖/自定义字段/甘特** | 偏项目管理，和目标用户不匹配 |

### 明确不建议做（v1.x）

- 看板、甘特、四象限、习惯打卡、番茄钟、倒数日、团队协作、多人共享。
- 这些是 TickTick/时光序的战场；轻单加进去会变成“又一个全能但慢的 Todo”，失去差异。
- 如果未来一定要做，建议独立模式/插件，不要污染主界面。

## 5. 90 天路线图（建议）

| 阶段 | 时间 | 交付 | 通过标准 |
|---|---|---|---|
| **第 1 阶段：可信的快** | 第 1–2 周 | 打包版基准、TaskList 虚拟化、桌宠延迟加载、内存优化 | 干净 Win11：冷启动 P50 <1s、P95 <2s；常驻 <150MB；1 万条滚动 60fps |
| **第 2 阶段：日常闭环** | 第 3–5 周 | 收件箱、通知完成/稍后、错过摘要、撤销、拖拽排序、行内编辑 | 7 天连续使用不丢任务；提醒闭环可完成；撤销覆盖完成/删除/移动 |
| **第 3 阶段：知识工作** | 第 6–8 周 | Markdown 预览、checklist、FTS5 搜索、命令面板、CSV/MS To Do/ICS | 10k 任务搜索 <50ms；导入 1000 条无错；键盘可完成 90% 操作 |
| **第 4 阶段：差异化** | 第 9–12 周 | 任务栏角标、农历/调休、只读日历同步、周复盘、桌宠迷你清单 | D7 留存 >35%；通知操作使用率 >20%；用户访谈中“快/干净/数据是我的”成为前三关键词 |

> 如果第 1 阶段性能不达标，不要继续加功能；先决定是优化 Electron 还是评估 Tauri。性能是这一定位的生命线。

## 6. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Electron 启动/内存达不到“最快”承诺 | 核心卖点崩塌 | 先做基准；TaskList 虚拟化、桌宠延迟加载、减少渲染进程；必要时评估 Tauri |
| 没有移动端/同步 | 用户手机场景断裂 | 短期 ICS/导出；中期 WebDAV/S3 可选同步；不急于自建云 |
| Microsoft To Do 免费 + Outlook | 免费市场被吸走 | 用本地/中文 NLP/键盘/数据所有权差异化；不要拼免费功能数量 |
| TickTick 功能面太全 | 迁移用户觉得“少东西” | 只接住“轻量/隐私/速度”子集；用导入器降低迁移成本，不追功能全 |
| AI/MCP 成为高端标配 | 高端用户流失 | 先 MCP Server + 可选自带 Key AI；不做云端 AI 绑定 |
| 桌宠影响专业感 | 劝退部分用户 | 默认关闭或首次引导可关；保留“专注模式”纯列表 |
| 免费本地产品变现难 | 长期不可持续 | 免费核心 + 付费同步/AI/高级统计；不做广告 |

## 7. 本周就能做的 5 件事

1. **用干净 Windows 机器跑打包版基准**：冷启动、内存、1 万条滚动，公布真实数字；不要再引用开发环境 4s。
2. **给 TaskList 加虚拟滚动**，并用 10k 任务压测；这是“快”的最低成本证明。
3. **加收件箱 + 通知“完成/稍后”**；这是日常闭环里用户最容易感知的两个缺口。
4. **加 Ctrl+Z 撤销 + 列表拖拽排序**；把“像 Things 一样顺手”补上。
5. **找 5 个目标用户访谈**：3 个 Things 用户（Windows 流亡者）+ 2 个 TickTick 迁移者；验证“愿意为本地/快/中文付多少钱”。

## 8. 最终判断

- **市场空位存在，但只够容纳一个“锋利的小产品”，不够容纳一个“全能挑战者”。**
- 轻单当前已经具备“锋利”的雏形：中文捕获、本地数据、Windows 集成、桌宠记忆点。
- 真正决定成败的不是再加 10 个功能，而是：
  1. 把“快”用可复现的数据证明；
