## 1. 定位与目标用户

### 1.1 要解决的三个问题
1. **慢**：Todoist / TickTick 的 Windows 客户端启动慢、输入卡、常驻占 CPU。
2. **重**：为了用 20% 的功能，被迫接受 80% 的复杂度（习惯、番茄、团队、AI 全塞进来）。
3. **不放心**：任务数据锁在云端账号里，导出困难，断网就废。

### 1.2 目标用户
- 主要：20–40 岁个人用户（学生 / 知识工作者 / 自由职业），每天 10–50 条任务。
- 次要：从 TickTick / Todoist 迁出、对性能敏感的用户。
- 明确不是：团队协作、企业项目管理、重度 GTD 玩家（v1 不覆盖）。

### 1.3 成功标准（v1）
- 冷启动到可交互 < 800ms，常驻内存 < 150MB。
- 用户 3 秒内能记下一条任务，不需要鼠标。
- 连续使用 7 天后，日活任务完成率 > 60%（自测口径）。

## 5. 核心流程

### 5.1 捕获（目标：3 秒）
1. 任意界面按 `Ctrl+Shift+Space` → 屏幕中央弹出输入条（不抢焦点之外的任何东西）。
2. 输入 `明天下午3点 交周报 #工作 @汇报 !高`。
3. 输入框下方实时显示解析结果 chips：`计划日 明天` `15:00` `清单 工作` `标签 汇报` `优先级 高`。
4. `Enter` 保存并关闭；`Ctrl+Enter` 保存并继续输入下一条；`Esc` 取消。
5. 解析失败的部分原样留在标题里，不丢内容。

### 5.2 规划（目标：2 分钟排完一天）
1. 打开「今天」，先看「逾期」区，逐条决定：今天做 / 改期 / 放弃。
2. 从「最近 7 天」把任务拖进「今天」，或按 `Ctrl+Shift+T` 设为今天。
3. 拖拽排序决定执行顺序；`Space` 完成任务。
4. 日历视图里可把任务从某天拖到另一天。

### 5.3 执行
1. 到点弹 Toast：「交周报 · 18:00」，按钮「完成」「稍后 10 分钟」。
2. 点「完成」→ 任务标记完成并写入日志；点「稍后」→ 10 分钟后再次提醒。
3. 托盘图标显示今日剩余数量角标（可选）。

### 5.4 复盘
1. 「已完成」按天分组，显示完成时间。
2. 「设置 → 数据」可导出 JSON/Markdown/CSV，或从备份恢复。

## 6. 关键规则

### 6.1 日期与时间
- 数据库统一存 UTC 时间戳；「计划日」存本地日期（`YYYY-MM-DD`），避免时区漂移。
- 全天任务：`due_all_day = 1`，提醒默认当天 09:00（可改）。
- 跨时区：v1 只支持本机时区；旅行导致时区变化时，按「本地墙上时间」解释。

### 6.2 中文自然语言语法（v1）

| 类型 | 支持写法 | 示例 |
|---|---|---|
| 相对日 | 今天/明天/后天/大后天/今晚/明早 | `明天 交报告` |
| 星期 | 周一…周日、本周五、下周三、下下周一 | `下周三 开会` |
| 绝对日 | 3月5日、3/5、2026-03-05、3月5号 | `3/5 交房租` |
| 模糊日 | 月底、下个月初、周末 | `周末 爬山` |
| 时间 | 上午9点、下午3点半、15:00、晚上8点、中午 | `下午3点半 评审` |
| 重复 | 每天、每周、每周一/三/五、每月5号、每月第2个周二、每3天、工作日 | `每周一 站会` |
| 优先级 | `!高` `!中` `!低` 或 `!1`…`!4` | `!高 修 bug` |
| 清单 | `#清单名` | `#工作 写周报` |
| 标签 | `@标签名` | `@汇报 写周报` |
| 转义 | 反引号包裹不解析 | `` `明天` `` |

- 解析顺序：时间 → 重复 → 优先级 → 清单 → 标签；未匹配文本保留在标题。
- 中文数字（三点、十五号）与阿拉伯数字都支持。

### 6.3 重复任务语义
- **按计划时间**：完成后，下一次 = 原定时间 + 周期（错过多次只生成下一次）。
- **按完成时间**：完成后，下一次 = 完成时间 + 周期（适合"每 3 天浇花"）。
- 编辑重复任务时弹窗询问：仅本次 / 本次及以后 / 全部。
- 删除同理。

### 6.4 完成与删除
- 完成任务：`status=1`，记录 `completed_at`，从当前视图移除（动画 200ms）。
- 删除任务：软删除 `deleted_at`，进回收站 30 天；子任务级联。
- 撤销：`Ctrl+Z` 支持完成/删除/移动的撤销（保留 20 步）。

## 7. 数据模型（SQLite）

```sql
-- 清单文件夹
CREATE TABLE folders (
  id          TEXT PRIMARY KEY,          -- uuid
  name        TEXT NOT NULL,
  sort_order  REAL NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL
);

-- 清单
CREATE TABLE lists (
  id          TEXT PRIMARY KEY,
  folder_id   TEXT REFERENCES folders(id) ON DELETE SET NULL,
  name        TEXT NOT NULL,
  color       TEXT,                       -- #RRGGBB
  icon        TEXT,                       -- emoji 或图标名
  sort_order  REAL NOT NULL DEFAULT 0,
  is_pinned   INTEGER NOT NULL DEFAULT 0,
  archived_at TEXT,
  created_at  TEXT NOT NULL
);

-- 任务
CREATE TABLE tasks (
  id             TEXT PRIMARY KEY,
  list_id        TEXT REFERENCES lists(id) ON DELETE CASCADE,
  parent_id      TEXT REFERENCES tasks(id) ON DELETE CASCADE,
  title          TEXT NOT NULL,
  notes          TEXT NOT NULL DEFAULT '',
  priority       INTEGER NOT NULL DEFAULT 0,   -- 0无 1低 2中 3高
  status         INTEGER NOT NULL DEFAULT 0,   -- 0待办 1完成
  scheduled_date TEXT,                          -- YYYY-MM-DD 计划日
  due_at         TEXT,                          -- ISO UTC 截止时刻
  due_all_day    INTEGER NOT NULL DEFAULT 0,
  rrule          TEXT,                          -- RFC5545 RRULE
  repeat_from    TEXT,                          -- 'due' | 'completion'
  reminder_at    TEXT,                          -- 下一次提醒 UTC
  completed_at   TEXT,
  deleted_at     TEXT,
  sort_order     REAL NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);
CREATE INDEX idx_tasks_list      ON tasks(list_id, status, deleted_at);
CREATE INDEX idx_tasks_sched     ON tasks(scheduled_date, status);
CREATE INDEX idx_tasks_due       ON tasks(due_at, status);
CREATE INDEX idx_tasks_parent    ON tasks(parent_id);
CREATE INDEX idx_tasks_reminder  ON tasks(reminder_at) WHERE reminder_at IS NOT NULL AND status = 0;

-- 标签
CREATE TABLE tags (
  id    TEXT PRIMARY KEY,
  name  TEXT NOT NULL UNIQUE,
  color TEXT
);
CREATE TABLE task_tags (
  task_id TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  tag_id  TEXT NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (task_id, tag_id)
);

-- 设置
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL          -- JSON
);

-- 全文索引
CREATE VIRTUAL TABLE tasks_fts USING fts5(
  title, notes, content='tasks', content_rowid='rowid', tokenize='unicode61'
);
```

- 排序用 `REAL` 的 `sort_order`（相邻取中值），避免整表重排。
- 所有时间字段 ISO8601 UTC；「计划日」是纯日期。
- 为未来同步预留：`id` 用 UUID、`updated_at` 单调递增、软删除。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Electron 内存/包体不达标 | 核心卖点失效 | 主进程轻量化；列表虚拟滚动；打包时裁剪；必要时评估 Tauri |
| `node:sqlite` 在 Electron 中不可用 | 数据层返工 | 抽象 Repository；备选 better-sqlite3（需 VS Build Tools） |
| 中文 NLP 解析不准 | 捕获体验崩 | 规则引擎 + 大量用例；解析结果可视化，允许手动改 |
| Windows Toast 不显示 | 提醒失效 | 设置 AppUserModelID；安装版注册快捷方式；文档说明 |
| 全局快捷键冲突 | 无法唤起 | 首次启动检测，冲突时引导改键 |
| 范围蔓延 | 4 周做不完 | 本 PRD 的「不做清单」为硬边界，新需求进 v1.1 |
